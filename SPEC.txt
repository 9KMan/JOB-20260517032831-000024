## 3. Core Workstreams

### Workstream 1: Graph Data Modeling
- Design node/relationship schemas for client's domain (knowledge graphs, social networks, or supply chain)
- Map relational schemas → property graph model (entities, relationships, attributes)
- Define labels, relationship types, and索引 strategies (composite indexes, full-text indexes)

### Workstream 2: ETL/ELT Pipeline for Graph Data
- Build Python-based ETL layer to extract from Postgres/MySQL REST APIs, CSV/JSON, S3
- Use Apache Airflow for pipeline orchestration with watermark-based incremental CDC
- Load into Neo4j (via Cypher `LOAD CSV` or Neo4j Python Driver) and Neptune (via Gremlin)
- Implement idempotent upserts (MERGE operations) to handle re-runs without duplication

### Workstream 3: Graph Query Optimization
- Profile Cypher queries with `EXPLAIN`/`PROFILE`
- Optimize Gremlin traversals: predicate pushdown, early filtering, vertex-centric indexes
- Implement query result caching (Redis) for frequently-accessed subgraph queries
- Build parameterized query library to prevent injection and encourage plan reuse

### Workstream 4: Data Integrity & Security
- Configure Neo4j authentication (LDAP/Active Directory integration)
- Set up Neptune IAM-db authentication
- Implement field-level encryption for PII in graph properties
- Build data validation layer (Python pre-load) to catch schema violations before ingest

## 4. Data Model (Neo4j Property Graph)

```
(:Source {id, type, label})
(:Entity {id, name, properties})
(:Relationship {type, from_id, to_id, properties, weight, created_at})

Example: Supply Chain Knowledge Graph
  (Supplier)-[:SUPPLIES {qty, lead_time}]->(Component)
  (Component)-[:ASSEMBLES_INTO {ratio}]->(Product)
  (Warehouse)-[:STORES {stock_level}]->(Component)
```

## 6. Technical Decisions

1. **Neo4j vs. Neptune:** Neo4j for primary dev (better Cypher ergonomics, lower cost for <10M nodes); Neptune as cloud-managed fallback for multi-region HA
2. **ETL:** Python + Apache Airflow over managed alternatives — fine-grained control over graph transformations and retries
3. **CDC:** Watermark-based incremental (no full re-loads) — `updated_at` column as watermark, stored in Airflow XCom
4. **Query optimization:** Cypher `EXPLAIN` first, then apply index hints; Neptune uses Gremlin with profile() step
5. **Graph application API:** FastAPI over Flask — native async, Pydantic validation, OpenAPI auto-docs
